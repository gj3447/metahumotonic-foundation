# 라이선스 허점 검토 후속: 초안과 CHU 참여·정산 실험

사용자 요청: “다음 작업 쭉쭉 이어서 진행해줘봐 ㅇㅇ”.
[원문](user-verbatim.txt)은 USER_PRIMARY, 아래 설계와 수치는 SECONDARY_AI다.
[앞선 적대적 검토](../license-adversarial-review/README.md)의 후속 작업이며,
공개 규범 비준이나 독립 법률 검토가 완료된 문서가 아니다.

**저작권 사용 허락, 하드웨어 접근 승인, CHU 서비스 구매를 각각 확인한다.**
공유에 참여했다는 이유로 다른 참여자의 연산을 무제한 청구할 수 없도록,
기존 시장 원장 위에 참여 승인을 붙였다. 실제 운영자와 소유자의 인증,
원격 장비 권한 발급, 독립 계량 및 MHC 발행은 아직 구현하지 않았다.

현재 적용 LICENSE는 **1.2 그대로**다. 1.3은 [전체 검토 초안](../../../licenses/MetaHumotonic-1.3-DRAFT.txt)이며,
기존 공개 저장소 63개의 라이선스를 다시 교체하지 않았다.

| 7 | 권리·이전 허락·AI 작성 관여·확인되지 않은 부분을 추적하는 명세 |

대응 소스 의무와 3년 제공 기간은 **새 AI 제안**이다. 사용자가 이미 그 기간을
결정했다는 뜻이 아니다. 제3자 AGPL에 MHL을 덧씌우거나 과거 수령자의 MIT·MHL-1.2
선택권을 지우는 수단으로 사용할 수 없다. 새 의무의 호환성과 집행 가능성은 검토 전이다.

의도적으로 미결정으로 남긴 것은 **소프트웨어 사용 규모에 비례한 기여율**이다.
작은 유효 VM으로 큰 규모의 자기 소프트웨어를 운영할 수 있는 1.2의 구조까지
이번 코드가 막았다고 주장하지 않는다. 막는 것은 이 실험 시장에서 잔고 없이
유상 서비스를 구매하는 행동이다. 무상 가격을 제시하거나 별도 보조금을 주는
제공자의 선택은 경제 정책이며, 소프트웨어 라이선스가 자동 결정하지 않는다.

## 참여 프로토콜과 신뢰 경계

1. 자원 소유자가 제공 대상·운영자·목적·상한·기간·조건 및 권리 검토 문서 해시를 제안한다.
2. 소유자의 `LICENSE`, 소유자의 `ACCESS`, 운영자의 `OPERATOR` 승인을 따로 기록한다.
3. 운영자가 별개의 관측 ID로 도달성 확인을 기록해야 자원 견적을 게시할 수 있다.
4. 구매자는 가격·예산을 선택하고 잔고와 용량을 원자적으로 예약한다.
5. 실행 결과 확인 뒤 합의 단가로 지급하고 미사용 예약금을 돌려준다.
6. 장애·철회 시 대기 주문은 취소·환불한다. 실행 중 주문은 중지를 요청하고,
   종료 확인 전에는 용량을 다시 쓰지 않는다. 확인 불능 시 기존 시장의 격리 절차를 따른다.

실험의 승인 유효기간은 최대 1시간, 관측 유효기간은 30초다. 라이선스의 최대
14일을 바꾸는 규정이 아니라 로컬 시험용으로 더 짧게 잡은 상수다. 새 관측이
승인 기간이나 기존 가격 제안의 만료를 늘리지 않는다. 만료·철회한 참여는
새 명세서 ID와 새 승인이 필요하며, 갱신 요청을 자동 전송하지 않는다.

실제 동작과 문서의 법적 요구를 혼동하지 않도록 다음 한계를 유지한다.

- `actor` 문자열은 인증이 아니다. 이 코드와 DB를 소유한 로컬 호출자는 신뢰한다.
  역할이 맞는 이름을 외부인이 입력하는 것을 막을 네트워크 인증은 없다.
- `rights_review_sha256`은 정확한 문서를 가리킬 자리다. 그 내용·권리자·법적 효력을
  검증하지 않는다. 승인 기록 역시 실제 이용자가 중요한 조건을 이해했다는 증명이 아니다.
- `observe`는 네트워크 검사 대신 신뢰하는 로컬 관측을 받는다. 실제 소유자 동의나
  SSH/root 권한을 만들지 않는다. 완전한 명세 예시의 모든 필드를 검증하는 구현도 아니다.
- 같은 USL 식별자의 중복 등록과 같은 등록 자원의 동시 약정을 막지만, 한 물리 장비를
  서로 다른 ID로 거짓 등록하는 Sybil 공격은 막지 못한다.
- 원래의 `Market` API, DB 직접 수정, 다른 프로세스로 이 규칙을 우회할 권한이 있는
  사람을 막는 보안 경계가 아니다. 서버의 단일 진입점·인증·서명·내구성 강화는 후속 작업이다.
- `sum` 결과는 독립 수식으로 확인한다. 예제 CPU 사용량은 합성값이며,
  실제 로컬 worker의 측정도 독립적인 원격 장비 증명이나 연산 담보가 아니다.
- 원장에 미리 배정한 `SIM-MHC`만 이전한다. 등록·지급 사건에서 새 자산을 발행하지 않는다.
  실제 MHC, 실시간 HSWM, 유료 LLM, 원격 하드웨어 연결은 없다.

## 재현

저장소 루트에서 실행한다. Python 표준 라이브러리를 사용하고, 실제 worker 시험은 Linux용이다.
일반 사용 환경에서는 다음 명령으로 가상 당사자의 동작을 볼 수 있다.

```sh
python3 -m market.participation_demo
python3 -m unittest market.test_participation market.test_market -v
```

관리형 Proxmox 작업 환경에서는 동일 명령을 `proxmox-scratch run`으로 감싸고,
저장 공간·시간 제한을 따른다. 거부된 검증을 실행 성공으로 취급하지 않는다.

예제의 예상 흐름은 초기 `sponsor=1000, alice=0, bob=0`에서 가입 후에도
alice의 잔고가 0이고, sponsor가 구매한 성공 결과에 10을 지급한 뒤 alice가
bob의 서비스에 4를 지불하여 `990, 6, 4`가 되는 것이다. 실제 가치 창출·원가·수요의
측정 결과가 아니라 **동일 예산을 두 번 쓰거나 참여만으로 돈이 생기지 않는지**의 예제다.

기존 `market.projection`은 이 원장의 거래를 JSON-LD로 투영할 수 있다.
그 회계 그래프와 `verify_snapshot`은 새 참여 승인의 완전한 의미 검증기가 아니다.
이번 기록은 별도 KG에 저장하거나 새 온톨로지 채택을 선언하지 않는다.

## 이번 검증 결과

**참여 시험 19개와 기존 시장 시험 25개, 합계 44개가 통과했다.** 실제 로컬
worker 실행과 철회 후 프로세스 종료·환불도 포함한다. 전체 시험 시간은 79.220초였다.
파일별 권리 명세 해시, JSON·Python 구문, 로컬 문서 링크와 발견 사항별 시험 참조도 확인했다.

별도 데모 CLI 실행은 공용 관리형 작업 슬롯 한도로 세 번 연속 거부되어 **미실행**이다.
위 예제 잔고는 예상값이며 데모 실행 관측값으로 기록하지 않았다. 이 예제와 같은
기여 대금·구매 흐름은 통과한 `test_small_membership_does_not_create_buying_power`에서
검증하지만 CLI 전체 실행 성공을 대신하지 않는다. 실행 슬롯을 확보한 뒤 위 명령으로
추가 확인할 수 있다. 보호 장치를 우회하거나 다른 작업의 예약을 해제하지 않았다.

새 온톨로지·SHACL·정본 그래프·투영 코드는 변경하지 않았고 전체 그래프 검증은
이번에 재실행하지 않았다. 상세 상태와 명령은 [검증 기록](verification.json)에 남긴다.

## 다음 구현 순서

1. 권리 명세를 파일·변경분과 이전 배포까지 확대하고, 실제 책임 주체가 확인한다.
2. 등록 서버에서 당사자 키 인증·서명된 불변 명세·철회 목록·감사 기록을 구현한다.
   기존 코드에서 `actor`를 외부 요청 값으로 그대로 넘기면 안 된다.
3. 명시적으로 승인된 시험 VM 한 대에서 기간·비용·격리·중지를 강제하고,
   재접속 실패·시계 변화·네트워크 분할·중복 등록을 시험한다.
4. 독립 계량과 결과 수락, 분쟁·환불을 갖춘 소규모 유상 서비스를 검증한다.
   기여의 양이 커질수록 실제 구매 가능한 서비스가 늘어나는지 수요와 원가로 확인한다.
5. 그 증거를 근거로 MHC 발행·만기·상환·준비 용량을 설계한다. 라이선스 동의나
   자기 보고 사양만으로 담보 코인을 먼저 발행하지 않는다.

라이선스는 권한 있는 저작물의 사용 조건을 정할 수 있지만, 시장 수요나
물리 용량을 만들어내는 증명이 될 수는 없다. 재단이 제공할 핵심은 공동 규칙과
검증 가능한 서비스다. 그것이 유용해서 참여·거래가 늘어나는지를 다음 실험에서 봐야 한다.
